## Build & test
Monorepo, no root build marker: Rust crate in `gb-core/` (compiled to WASM by wasm-pack), React/Vite app
in `gb-web/` (npm, `package-lock.json`). Run every command from its directory.
- **Build:** `cd gb-core && wasm-pack build --target web --out-dir pkg` then `cd gb-web && npm ci && npm run build` (`tsc -b && vite build`; needs the WASM `pkg/` first)
- **Full test:** `cd gb-core && cargo test --release --no-fail-fast` and `cd gb-web && npm test` (Node's test runner over `src/**/*.test.ts`)
- **Single-suite filter (per-task, fast):** `cd gb-core && cargo test --release --test <file stem in gb-core/tests/, e.g. blargg, acid2, cgb, sgb> [<name>]` (lib unit tests: `cargo test --release --lib <name>`) · web: `cd gb-web && node --test src/path/to/file.test.ts`
- **Format/lint apply:** `cd gb-web && npx eslint . --fix` · `cd gb-core && cargo fmt`
- **Format/lint verify (the gate):** `cd gb-web && npm run lint` (typecheck: `tsc -b`, part of `npm run build`). `cargo fmt --check` / `clippy` are NOT CI gates.
- **Prerequisites / caveats:** run `./scripts/fetch-test-roms.sh` first — test ROMs are downloaded into
  `gb-core/test-roms/` (gitignored). CI sets `CARTOUCHE_REQUIRE_ROMS=1` so a missing ROM fails instead of
  skipping. Always pass `--no-fail-fast` (cargo otherwise stops at the first failing binary). Rust needs the
  `wasm32-unknown-unknown` target and `wasm-pack`; Node 24 in CI. `gb-web/rcheevos/build.sh` needs
  emscripten (only when touching rcheevos; `src/vendor/rcheevos.js` is generated, never hand-edited).

## Conflict hot-spots (merge-with-main resolutions)
| File | Why it collides | Resolution |
|------|-----------------|------------|
| `CHANGELOG.md`, `.release-please-manifest.json`, versions in `gb-web/package.json` / `gb-core/Cargo.toml` | release-please-managed | **never edit** — take `main`'s side |
| `gb-web/package-lock.json`, `gb-core/Cargo.lock` | lockfile churn | **regenerate** (`npm install` / `cargo build`), don't hand-merge |
| `gb-core/src/lib.rs` | every feature adds wasm_bindgen exports | **union** exports; keep the public WASM API backward compatible |
| `gb-core/src/gameboy.rs`, `memory.rs`, `cartridge.rs`, `ppu.rs` | core hot paths and save-state layout touched by most emulation work | real semantic merge — understand both intents; save-state fields must stay in one agreed order |
| `gb-web/src/store/settingsStore.ts` | every setting adds a field + default | **union** fields/defaults |
| `gb-web/src/i18n/{en,fr,es}/*.ts` | every UI string lands in all three locales | **union** keys, keep en/fr/es in step (`i18n.test.ts`, `leftovers.test.ts` check) |
| `README.md`, `docs/`, `THIRD_PARTY_NOTICES.md` | parallel features document themselves | **union** |
| `gb-web/src/vendor/rcheevos.js` | generated | **regenerate** with `gb-web/rcheevos/build.sh` |
- **Rule of thumb:** union additive files, regenerate derived files, never touch release-please's files;
  same-logic-both-sides is a real semantic conflict — understand both intents or stop.
